为安全治理团队实现敏感操作的双岗复核排班器，仅处理合成工单、人员资格与日历，不连接真实业务系统。每个工单属于一个资产责任部门，可选若干整数分钟的半开时段。每次复核必须同时安排一名安全复核人和一名业务复核人，两人必须不同、部门也不同，且均不属于资产责任部门。人员须具备对应资格，整个时段可用，不能与其已有预留重叠；同一人相邻两次复核之间至少间隔给定的休息分钟数。一人可具备两类资格，但不能在同一工单兼岗。所有标识使用给定的 ASCII 字符串，费用与权重均为非负整数。

工单分为必排和可选。所有必排工单必须安排；可选工单先最大化安排权重总和，再最小化时段费用与两名复核人的岗位费用之和，最后取唯一的字典序最小方案。规范顺序为按工单 ID 排列的键向量：已安排项为 (0,开始分钟,结束分钟,安全复核人ID,业务复核人ID)，未安排项为 (1)。如果必排工单不能全部安排，返回其中基数最小的不可排子集，同样大小取排序后的工单 ID 列表字典序最小者；不可排依据包含当前固定预留与人员资格，不能只返回搜索过程中碰到的一组冲突。支持至多12个工单、10名人员、每工单至多4个候选时段。不得用贪心近似冒充最优结果。

人员资格、不可用时段和已预留日历由 SQLite 保存为单调版本。规划只读取固定版本，不占用日历。确认计划时必须在一个事务内重读版本并核对完整方案，版本变化就拒绝，不能自动换人或改时段；全部新预留、版本推进与成功回执原子提交。相同请求 ID 和相同输入只能重放原回执，不再占位；同 ID 改输入必须拒绝。失败不能留下部分工单或单边复核人预留。历史回执保持原样，后续资格调整只影响新的规划与确认。

用两个独立 Windows 工作进程和同步点固定两份计划争用同一人员时段、规划后资格被撤回的顺序；真实终止自己的工作进程于预留已写入未提交、已提交未返回两处，再重启按 ID 核对回执和占位。用至多6个工单的小样本穷举独立核对最优目标、唯一方案与最小不可排子集，另测休息间隔恰好相等、半开边界、同人双资格、输入顺序打乱和可选工单放弃后的全局最优。

在 Windows 原生 Python 3.12、标准库和 CPU 环境下实现，全部输入自行合成，离线测试。交付源码、README、可重放 cases.json 和自动化测试。提供 python -m solution --input cases.json --output result.json 与 python -m unittest discover -s tests -v。测试须断言具体结果，README 写明规则、输入输出、错误码和实测结果。
